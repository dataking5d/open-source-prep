# open-source-prep

把本地项目、工具或技能整理成可审阅的公开候选版；用户明确要求发布时，继续核对账号、上传并验证远程内容。

## 它处理什么

- 检查当前文件、Git 索引和相关历史中的隐私、许可、嵌套仓库与目录联接。
- 在独立副本中准备公开内容，补齐真实文档和不含客户资料的合成演示。
- 运行项目实际需要的验证，核对发布清单、ZIP、暂存文件和最终远程内容。
- 区分准备与发布授权；核对实际目标账号和同名仓库，遇到不确定推送结果时先查询状态。

账号、代理端口、项目许可证和测试数量按当前任务取得，不沿用旧项目常量。
这是供 Agent 读取的工作流指令，不是独立运行的扫描程序；模式检查不能保证排除所有未知敏感内容。

## 安装

克隆仓库：

```text
git clone https://github.com/dataking5d/open-source-prep.git
```

将整个 `open-source-prep` 目录放入你所用 Agent 支持的技能目录，或通过其本地技能加载入口选择该目录。
最终结构应为 `技能目录/open-source-prep/SKILL.md`；保留 `references/` 和 `agents/`，不要只复制一个文件。
目标已有同名技能时，先核对版本与来源，避免直接覆盖。

此技能自身没有 Python 或 Node 运行依赖；执行项目验证时按项目安装所需依赖，Git 历史检查需要 Git。
发布时还需要具有目标仓库权限的专用连接或 CLI。具体条件见 [SKILL.md](SKILL.md)。

## 使用示例

在能加载 SKILL.md 的 Agent 中使用；Codex 可显式调用 `$open-source-prep`，其他工具按其技能调用方式或自然语言使用。

- “用 open-source-prep 为这个目录做开源前准备，先生成候选包和报告。”
- “用 open-source-prep 检查这几个项目，客户资料和旧历史保留在本地。”
- “将已经批准的候选版上传到我指定的 GitHub 账号。”

准备模式交付候选源码、审阅包、验证结果和待定事项。发布模式在已有明确授权的范围内继续，交付仓库链接与远程核验回执。
准备不会自动公开项目，已存在的仓库也不会被盲目覆盖。
