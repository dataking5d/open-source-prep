# 隐私检查参考

## 检查对象

按项目证据确定范围，不仅扫描 Git 默认列出的文件。检查当前工作树、索引、忽略目录、准备中的 ZIP/清单，以及需要继承或公开的历史引用。

| 对象 | 重点 |
|---|---|
| 配置与凭据 | 环境配置、私钥、证书、令牌、认证 URL、浏览器状态；本地配置不能仅改扩展名后上传 |
| 个人与客户资料 | 联系方式、学号、客户正文、姓名与客户关联、内部评价、付款/订单记录 |
| 派生材料 | 向量/知识库索引、摘要、分析结果、截图、日志、golden、测试 fixture、打包文献 |
| 机器上下文 | 用户目录、挂载盘、个人知识库路径、内部主机名、工作台记忆与配置 |
| 历史与链接 | 已删除但仍在 Git 的材料、其他分支/标签、gitlink、嵌套仓库、symlink/junction |

版权作者、贡献者名字、合法引用来源和纯合成资料不当然属于机密；判断实际来源与公开权限。

## 搜索与输出

优先使用专用搜索或 `rg`。先用不跟随链接的遍历识别外部 symlink/junction。文件搜索仅针对已确认的普通路径，不使用跟随链接选项。
Git 的未跟踪目录枚举在 Windows 上也可能展开 junction，因此第一轮先禁用该枚举，再以普通路径清单补查新文件。
第一轮内容搜索只输出文件名，例如：

```powershell
rg -l --hidden --glob '!.git/**' --glob '!node_modules/**' --glob '!.venv/**' 'api_key|apikey|password|secret|token|wxid_' .
git ls-files --stage
git status --short --untracked-files=no
```

上述词用于定位候选，不等于发现有效凭据。宽泛关键词可能同时命中正常环境变量和规则文档。
需要核实内容时，局部读取并遮盖值；自动结果仅输出相对路径、风险类别、必要行号/对象 ID。
不要使用会把整行真实凭据打印到聊天或公开日志的批量搜索。历史 blob 的扫描也按相同规则遮盖。

可用以下结构识别凭据，但须结合工具和格式判断误报：

- 模型令牌前缀与长随机主体：`sk-(?:proj-|ant-)?[A-Za-z0-9_-]{20,}`。
- GitHub/GitLab 等访问令牌前缀、云访问 ID、私钥 PEM 标记。
- 带用户名与口令的连接 URL、明文凭据赋值、会话 Cookie。
- Windows 用户目录、POSIX 主目录、个人挂载路径；客户标识从本次资料提取，不能写死旧案例的姓名。

环境变量名、散列值、公开 commit SHA 或演示占位符不是凭据本身；不盲目替换。
路径应按程序实际需要改成相对路径、环境配置或已有路径发现方式，不能用不可运行的文字替换掩盖问题。

## 跟踪状态与历史

`.gitignore` 只影响忽略行为；已跟踪文件、旧 commit、其他分支和标签仍可能包含私密内容。
`git ls-files --stage` 的 160000 是 gitlink，不是普通文件。先核对来源、实际依赖和许可，再决定公开方式；缺少子模块配置的记录不能当完整源码复制。

需要查历史时，可枚举可达对象并只读取相关 blob；二进制材料先按路径和来源审核，文本模式扫描不足以证明它们无隐私。
大体积、不可读、权限不足或扫描不支持的部分要列明，不把漏扫记为零命中。

发布新快照可不携带私有历史；原历史本地保留。若此前凭据已经公开，移除文件不能撤销凭据，应提示其所有者处理暴露后的轮换，并在明确授权下处理远端历史。不要自动进行不可逆改写。

## 最终检查

- 公开清单对应经过审核的文件；原配置、客户案例及审计材料未混入包。
- 当前内容、暂存内容、ZIP 与最终提交分别核对。
- 必要图片或二进制资源经过来源与元数据复核。
- 报告扫描范围、工具/规则、命中类型、未覆盖范围和具体处理，不输出敏感原文。
